# IMPLEMENTASI QUIS — Platform Live Quiz (MVP Lengkap)

Baca `documentation/PRD.md` (sumber kebenaran cakupan MVP) dan `documentation/IMPLEMENTATION_PLAN.md` (rencana teknis 6 fase).

## Tugas

Implementasikan **seluruh MVP Quizzly** sesuai plan: Fase 0 → 1 → 2 → 3 → 4 → 5 (Fase 5 cukup langkah 8-10: Dockerfile produksi realtime, docker-compose.prod.yaml + Nginx, health check & logging, dokumentasi; skip load test k6/artillery yang butuh infrastruktur eksternal, tapi tulis skripnya).

## Aturan Binding (WAJIB)

1. **Cakupan MVP terkunci** di PRD bagian 7. Jangan implementasikan fitur di luar cakupan (AI, mode tim, async, kuis publik, dll).
2. Nama event socket HANYA di `shared/events.ts`. Jangan pernah tulis string event literal di tempat lain.
3. Payload ke peserta TIDAK BOLEH memuat `isCorrect`. Selalu lewat `toPlayerPayload()`. Tulis unit test yang gagal jika `isCorrect` muncul di payload peserta.
4. Perhitungan waktu skor selalu jam server. Timestamp klien hanya untuk tampilan hitung mundur.
5. Pakai komponen yang sudah ada di `components/ui/` sebelum tambah dependensi. @dnd-kit, recharts, @tanstack/react-table sudah terpasang — pakai.
6. Schema selalu lewat `db:generate` + migrasi, jangan edit manual file migrasi existing.
7. **UI Bahasa Indonesia** sebagai bahasa utama (PRD 11.4: default ID).
8. Scoring: implementasi PERSIS rumus PRD 5.1-5.5, termasuk clamp, toleransi 500ms, tie-break 4 level.
9. Tulis test dulu untuk scoring (8 kasus di plan bagian 5) dan `toPlayerPayload()` (anti-kebocoran isCorrect), baru implementasi.
10. Server realtime: state otoritatif di memori, batch insert `participant_answer` saat soal ditutup (bukan per jawaban).

## Struktur Wajib

- `shared/` dipakai app DAN realtime (events.ts + types.ts)
- `realtime/` layanan Socket.IO terpisah (Node + TS + socket.io + Drizzle ke Postgres sama)
- `db/schema/quiz.ts` — 6 tabel: quiz, question, answerOption, gameSession, participant, participantAnswer
- Partial unique index PIN: `CREATE UNIQUE INDEX session_active_pin_unique ON game_session (pin) WHERE status IN ('lobby','in_progress')`
- `lib/scoring.ts` — fungsi murni
- `lib/pin.ts` — PIN 6 digit acak, retry 10x
- `lib/validators/` — zod
- Env baru: GAME_TOKEN_SECRET, REALTIME_PORT=4000, NEXT_PUBLIC_REALTIME_URL, UPLOAD_DIR, MAX_UPLOAD_MB=5

## Urutan Kerja

Kerjakan fase berurutan, JANGAN loncat. Setiap fase: selesai → verifikasi (build/test) → laporkan → lanjut.

- **Fase 0**: schema quiz.ts + shared/ + realtime/ scaffold + docker-compose service + Vitest kedua sisi. Selesai jika: dev :3000, realtime :4000 /health OK, db:studio 6 tabel.
- **Fase 1**: CRUD kuis + editor (dnd-kit reorder) + upload gambar + validasi kesiapan.
- **Fase 2**: PIN + /api/game/token + game-manager + lobby realtime + join page + presenter lobby + time:sync.
- **Fase 3**: scoring (test dulu) + state machine lengkap + timer server + player:answer + toPlayerPayload + leaderboard + UI presenter & peserta + reconnect + game:over.
- **Fase 4**: riwayat sesi + laporan (ringkasan, tabel peserta, analisis per soal, soal tersulit) + ekspor CSV + hapus sesi.
- **Fase 5** (terbatas): Dockerfile realtime prod + docker-compose.prod.yaml + Nginx (WebSocket upgrade) + health check & logging + dokumentasi deployment + skrip load test.
